# Contributing

This is a real, personal Mac setup that is also useful as a reference or a
forkable base. Keep it practical: make changes that are safe on a new machine,
easy to understand in a terminal, and reversible when they touch user state.

Before proposing a change, read the [code of conduct](CODE_OF_CONDUCT.md),
[security policy](SECURITY.md), and [operations guide](docs/OPERATIONS.md).

Before opening a change, run:

```sh
gofmt -w *.go internal/*/*.go
go test ./...
go vet ./...
go run . --dry-run install
```

Do not add credentials, OAuth files, caches, package locks generated by a tool,
or absolute machine paths. Config that differs by computer belongs in an
ignored local file, such as `config/fish/conf.d/90-local.fish` or
`home/gitconfig.local`.

Changes to linking behavior need a test in `internal/link`. The invariant is
simple: existing user files are backed up, never deleted.

Configuration proposals should name the concrete workflow they improve and
explain what happens on a fresh machine, an existing machine with user files,
and a fork. Keep personal preferences in local overrides unless they make a
good, documented shared default.
